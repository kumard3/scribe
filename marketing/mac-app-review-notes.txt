BOLKIT FOR MAC, REVIEW NOTES

NO ACCOUNT, NO PURCHASES
No account, login, backend, purchase or subscription; no demo credentials needed. The iPhone version is already on the App Store under this app record.

WHAT IT DOES
Dictation and meeting transcription for the Mac. Hold a key, speak, let go, and the text is pasted into the app you are typing in. It can also record a call and transcribe it with speakers separated. Models run on the Mac, it works offline, and we operate no server.

HOW TO REACH THE MAIN FEATURES
1. Launch. Bolkit lives in the menu bar (microphone icon), no Dock icon. A setup guide opens on first launch and asks for Microphone and Speech Recognition, then Accessibility and Input Monitoring.
2. Open TextEdit, hold fn (Globe), speak, let go: the transcript is pasted at the cursor. Control-Option-Space toggles dictation. No download needed: the default engine is Apple's speech recognizer.
3. Menu bar > Record meeting… opens the Recorder. Pick "No screen" (audio only) or a screen/window thumbnail, then Start recording. macOS asks to record system audio (and Screen Recording if a screen is picked). An indicator at the top shows the timer and Stop; transcript, speakers, summary and video appear under Dashboard > Meetings.
4. Menu bar > Record screen… records only the screen (with mic and Mac sound) to Movies > Bolkit, playable under Dashboard > Screen.
5. Optional: when a call app (Zoom, Teams, a browser on Google Meet) turns on the mic, a "Record this meeting?" card appears. Nothing records until the user presses Record. It can be turned off in Dashboard > Meetings.
6. Menu bar > Transcribe audio file. Dashboard > Models lists optional one-time downloads of offline speech models.

WHY EACH PERMISSION
- Microphone: to hear the user.
- Speech Recognition: Apple's on-device recognizer is the default engine.
- Accessibility: when the user stops speaking, Bolkit puts their own transcript on the pasteboard and posts one Command-V (CGEvent post) so it lands in their app. It does not use AXUIElement and never reads other apps' content. Voice typing is itself an accessibility aid. Without it the transcript is only copied.
- Input Monitoring: a listen-only tap on modifier changes (flagsChanged), so holding fn starts and stops dictation. No other keystrokes are read or stored.
- System audio: only during a meeting recording the user starts, for the other side of the call.
- Screen Recording: only when the user picks a screen or window in the Recorder (ScreenCaptureKit); its thumbnails and the on-device suggestion of the call window use the same permission. Recordings stay on the Mac.
- Movies folder (assets.movies.read-write): screen-only recordings go to Movies > Bolkit.
- Mic-in-use check: reads which apps have the mic open (Core Audio process list) only to offer the card above. Nothing is stored or sent.

EXTERNAL SERVICES
Apple Speech (SFSpeechRecognizer, SpeechAnalyzer); Apple Foundation Models on device for summaries; Hugging Face and GitHub Releases for static downloads of optional models (nothing sent up); optionally Ollama, a local server the user runs, for text cleanup. No auth provider, payments, analytics, ads, crash reporting or backend of ours.

REGIONAL DIFFERENCES
None.

REGULATED INDUSTRY AND THIRD-PARTY MATERIAL
Not regulated; a productivity utility. Models are public open-weight releases (Whisper, MIT; NVIDIA NeMo via k2-fsa/sherpa-onnx, Apache 2.0/CC-BY; Google Gemma, Gemma Terms of Use). Downloads are weights, not code. Source is MIT at https://github.com/kumard3/scribe.

TESTED ON
MacBook Pro 14-inch (M3 Pro), macOS 27.0 (26A428). Build 1.3.3 (7) ran in the App Sandbox: a meeting recording with system audio and a screen clip, switching the shared window mid-call, and a screen-only recording to Movies > Bolkit all worked. This build (8) adds only a fix that keeps the recording indicator at the notch in full screen, and deleting meetings. Needs macOS 14.0+ (meeting recording 14.4+).
